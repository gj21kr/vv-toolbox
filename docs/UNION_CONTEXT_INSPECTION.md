# MCA 병변 후보의 주변 혈관 간격 검사

우측 MCA `FJ1692:e0`의 폐곡면 후보를 나머지 1,080개 파생 중심선·반경 경로와 대조했다. 원본 Atlas 표면 간 충돌이나 해부학적 연결을 확정하는 검사가 아니다.

| 판정 | 평활화 전 | 평활화 후 |
|---|---:|---:|
| 경계 상자로 분리 입증 | 1,064 | 1,064 |
| 삼각형 전체 거리 하한으로 분리 입증 | 10 | 11 |
| 다른 경로 프로파일 내부의 정점 검출 | 5 | 5 |
| 분리도 겹침도 입증하지 못함 | 1 | 0 |

양쪽 결과 모두 `REVIEW_REQUIRED`다. 겹침 정점이 검출된 경로는 `FJ1654:e0`, `FJ1660:e0`, `FJ1682:e0`, `FJ1694:e0`, `FJ1718:e0`다. 정상 접합, 기존 프로파일 오차, 병변 생성으로 추가된 간섭을 아직 구분하지 않았다. 최소 정점 하나의 위치와 원래 모혈관 프로파일 값을 보관하되, 그 정점을 전체 겹침 영역의 대표값으로 해석하지 않는다.

## 겹친 정점 전체의 위치 검사

평활화 후 후보에서 다른 프로파일 내부에 있는 모든 정점을 수집하고 원래 모혈관 프로파일 값을 계산했다. 부호 판정에는 ±0.000001 mm 수치 밴드를 사용하며, 이를 임상 허용 오차로 해석하지 않는다.

| 상대 경로 | 내부 정점 수 | 원래 모혈관 바깥 정점 수 | 모혈관 field 최댓값 (mm) |
|---|---:|---:|---:|
| FJ1654:e0 | 11 | 8 | 0.056069 |
| FJ1660:e0 | 691 | 357 | 0.063541 |
| FJ1682:e0 | 1,382 | 730 | 0.059265 |
| FJ1694:e0 | 553 | 291 | 0.069424 |
| FJ1718:e0 | 432 | 214 | 0.058520 |

검출된 정점은 원래 모혈관 내부 또는 그 field 값이 0.070 mm보다 작은 바깥 영역에 있다. 이 결과는 돔 원위부의 큰 관통보다 모혈관 주변 접합·표면 이산화 영향을 먼저 조사할 근거다. 그러나 삼각형 내부만 교차하는 경우를 배제하지 않으므로 병변 간섭 없음이나 정상 접합으로 승인하지 않는다. Field 값은 이 구현의 선형 반경 프로파일 값이며 원본 표면까지의 정확한 거리로 해석하지 않는다.

정점 수는 삼각분할 밀도에 의존하며 겹침 체적이 아니다. JSON에는 각 겹침 정점 집합의 경계 상자, 모혈관 안/표면 밴드/밖 개수, field 범위와 최대 field 정점 주소를 저장한다. 모혈관 형상이 없으면 상대 위치 판정은 `UNKNOWN`이다. 관련 Docker 단위 검사는 5개 통과했다.

검사는 각 삼각형을 감싸는 구와 각 경로의 최대 끝점 반경 capsule을 사용한다. 양의 거리 하한은 삼각형 전체의 분리를 입증한다. 음의 하한만으로 겹침을 선언하지 않으며, 내부 정점이나 내부 표본 증거가 없으면 `UNKNOWN`으로 유지한다. 정점이 모두 바깥에 있다는 이유만으로 통과시키지 않는다.

정점 증거가 없는 미분리 삼각형에는 내부 표본 검사를 추가했다. 삼각형을 네 부분으로 나눠 최대 3단계까지 검사하며, 상대 경로당 표본 100,000개로 제한한다. 내부 표본이 프로파일 안에 있으면 원래 face index·barycentric 좌표·XYZ·field를 겹침 증거로 저장한다. 검출 실패는 분리 입증이 아니므로 `UNKNOWN`을 유지한다. 이미 정점 겹침을 검출한 경로에는 이 추가 탐색을 실행하지 않으며, 전체 겹침 영역을 열거하는 기능이 아니다.

실제 후보 재검사에서 판정 수는 위 표와 같았다. 정점이 모두 바깥인 삼각형의 중앙 및 비중앙 교차 검출, 원래 삼각형으로의 좌표 복원, 표본 제한 도달 시 미확인 유지 등을 포함한 Docker 단위 검사 7개가 통과했다.

원본 사례 revision과 두 후보 파일의 SHA-256을 확인하고 입력 불변을 검사했다. 결과는 [검사 JSON](evidence/union-context-inspection.json)에 보관한다. 앱 적용은 하지 않았다. 원본 표면 충돌 검사, 정상 접합 분류, 전체 개발계획의 비겹침 승인 조건은 미완료다.

재현: 프로젝트 Docker 환경에서 `PYTHONPATH=src python scripts/inspect_union_context.py`.

## 사례별 실행

`vv-case surface-context <snapshot.json> <surface.npz> --parent-edge <edge-id> --sha256 <expected-hash>`는 저장된 다른 후보에도 같은 검사를 실행한다. 출력은 JSON이며 종료 코드는 분리 입증 0, 검토 필요 3, 입력 오류 2다. 코드 0은 명시된 다른 프로파일과의 분리만 의미하며 원본 Atlas 또는 임상 승인이 아니다.

검사 전 NPZ의 실제 바이트 해시, metadata의 사례 revision과 좌표계를 확인한다. 해시를 계산한 동일 바이트에서 배열을 읽으며 원본을 수정하지 않는다. 선언된 metadata와 바이트 일치를 검증하는 기능이고, metadata 자체의 독립적인 진위를 입증하지는 않는다. `--parent-edge`는 명시적으로 제외할 모혈관 ID이므로 생성 근거에 맞게 지정해야 한다.

실제 우측 MCA 평활화 후보에서 종료 코드 3, `REVIEW_REQUIRED`, 주변 경로 1,080개를 확인했다. CLI 출처 불일치·좌표계 불일치·입력 불변·상태별 종료 코드 및 관련 회귀 검사 **16 passed**.

추가 전체 Python 회귀 검사: **667 passed, 3 skipped, 330 warnings, 71.31초**. 건너뛴 3개는 컨테이너에 Node가 없는 화면 로직 검사이며 이번 실행에서 별도 재실행하지 않았다. 경고는 scikit-image의 NumPy 배열 shape 대입 폐기 예정 경고다. [전체 검사 기록](evidence/regression-surface-context.json)은 실행된 Python 검사와 미실행 UI·브라우저 검증을 구분한다. 이 결과를 해부학적 경계 승인이나 개발계획 완료로 해석하지 않는다.

## 앱 후보 로더

등록 ID `right-mca-saccular`로 읽기 전용 후보 로더를 추가했다. 저장된 형상·평활화 근거·간격 검사 근거의 해시와 사례 revision, 좌표계, 삼각형 인덱스, 주변 경로 개수와 판정 일관성을 확인한다. 원본 Atlas와 별도의 합성 후보로 반환하며 `REVIEW_REQUIRED` 항목과 검사 범위를 화면용 summary에 포함한다.

실제 파일 로딩 결과: 28,720개 정점, 57,436개 삼각형, 주변 프로파일 분리 1,075개, `REVIEW_REQUIRED`. 기존 장골 후보와 MCA 후보 로더 검사 **14 passed**. 이 검사는 위 전체 회귀 검사 이후의 변경을 대상으로 한다. 화면 선택 항목·서버 API 연결·브라우저 검증은 아직 미완료이며 현재 데모의 선택 목록은 바꾸지 않았다.

## 데모 연결

후속 구현에서 합성 후보 선택 메뉴에 우측 MCA 동맥류를 추가하고 `/api/source`의 명시적 `candidate_id` 선택을 연결했다. 후보 화면은 분리 경로 수, 검토 대상 ID와 상태, 원본 표면 충돌 미검사를 표시한다. 중심선 모드는 사례의 `centerline_mm`를 지원한다.

관련 검사 17개 통과. localhost:8093 실서버에서 MCA 후보 선택 → `REVIEW_REQUIRED` 상태 조회 → Atlas 복귀 → MCA 재선택을 확인했다. 이때 새 ID가 기존 요청 필드 검사에서 거부되던 문제도 수정했다. 서버는 Docker의 localhost 포트 매핑을 유지한다. 실제 브라우저 렌더링·메뉴 클릭·스크린샷 검증은 `NOT RUN`이며 API 검사를 시각 검증으로 표시하지 않는다.
