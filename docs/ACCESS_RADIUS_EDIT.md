# 전체 접근 모델의 반경 편집 검사

## 현재 검증 상태

| 대상 | 결과 |
|---|---|
| 실제 반경 요청·결과 표시·적용 차단·취소·Atlas 복원 | PASS, 1,118.344초 |
| 편집 형상의 전체 중심선 65개 | PASS |
| 편집 형상의 주변 혈관 788개 | FAIL: 4개 이웃의 접촉 쌍 추가 |
| 새 창의 실행 입력값 표시 및 계산 중 입력 잠금 | 실제 브라우저 PASS |
| 자기 접촉 검사 재사용 | 실제 브라우저 PASS, baseline 형상·전체 audit 정확히 일치, 1,097.485초 |

브라우저 흐름 PASS는 실패한 형상을 적용해도 된다는 뜻이 아니다. 적용 버튼 비활성화와 서버 HTTP 400 거부, 취소 후 입력 표면 해시 및 Atlas 복원을 확인했다. [왕복 기록](evidence/access-radius-roundtrip.json), [새 창 상태 기록](evidence/radius-live-progress-ui.json), [최적화 후 비교 기록](evidence/access-radius-roundtrip-reuse.json).

검사 재사용 후 실행도 주변 788개 검사 범위를 유지했다. baseline과 편집 형상 해시·전체 radius audit의 정확한 일치, 적용 HTTP 400, 취소 후 parent 복원 및 Atlas 복원 PASS이며 브라우저 오류는 없었다. `exports/access-radius-roundtrip-reuse/controls.png`와 `preview.png`를 직접 확인했다: 1.05/10/1 입력값, 적용 차단, 중심선 65개 PASS와 주변 FAIL 표시가 일치한다. 캡처는 software WebGL이며 GPU 성능 검증이 아니다. 1,118.344초 대비 1,097.485초는 동시 작업 환경의 단일 측정으로 일반적인 속도 개선을 입증하지 않는다.

## 대상과 고정 조건

목 내부 메시를 개선하고 원본 분지를 보호한 `resampled-access-protected` 후보에서 좌측 대퇴동맥 FJ2074를 편집한다. 원본 case의 FJ2074:e0 중심선을 사용하며 중심선 revision과 후보의 원본 revision이 일치해야 한다. Atlas와 실행 중인 화면은 변경하지 않는다.

| 항목 | 값 |
|---|---|
| 반경 배수 | 1.05 |
| 끝점 및 공유 경계 전이 길이 | 10 mm |
| 허용 최대 정점 이동 | 1 mm |
| 편집 대상 | 선택한 source에만 속하는 정점 |
| 고정 대상 | 공유 경계 정점과 다른 source의 정점 |

이는 편집 알고리즘 검사 조건이며 부위별 질환 프리셋이나 문헌상 정상 범위가 아니다. 중심선에 수직인 방향으로 정점을 변위시키고 끝점 및 공유 경계에서 변위를 줄인다. 실제 단면 반경이 모든 위치에서 정확히 1.05배가 된다는 의미는 아니다.

## 검사와 판정

1. 원본 case revision, 입력 표면 해시, 선택한 중심선 ID를 기록한다.
2. 공유 경계와 다른 source 좌표 보존, 이동 제한, 삼각형 퇴화·뒤집힘, 닫힌 양의 체적, 자기 접촉을 검사한다. 실패 시 조건을 자동 완화하지 않는다.
3. 편집 표면을 별도 파일로 저장하고 해시를 기록한다. 면 소유권은 유지하되 변경 좌표는 합성 출처로 취급한다.
4. 기존 접근 그래프의 65개 구간 전체를 편집 표면과 대조한다. 일부 경로만 통과해도 전체 PASS로 표시하지 않는다.
5. 주변 혈관과의 접촉·포함, 단면 측정, 해부학적 수용은 별도 검사다. 중심선 검사를 통과한 CANDIDATE는 앱 적용 승인이나 전체 편집 기능 완료가 아니다.

실행: Docker 내부에서 `PYTHONPATH=src python scripts/inspect_access_radius_edit.py`.

- 실제 모델 실행 기록: [access-radius-edit.json](evidence/access-radius-edit.json)
- 기본 반경 편집 및 적용/되돌리기 검사: [8개 PASS](evidence/access-radius-prerequisite-tests.xml)
- 산출물: 실행 기록의 `artifact` 및 `output_sha256`으로 식별한다.

진행 중에는 RUNNING과 현재까지 검사한 경로만 기록한다. 최종 상태는 실행 기록을 기준으로 판단한다.

## 실행 결과

반경 편집 표면은 CANDIDATE이며 기존 65개 그래프 구간 전체의 내강 포함 검사가 PASS다. 264개 정점이 이동했고 최대 이동은 0.313648 mm였다. 공유 경계·다른 source 정점과 면 인덱스는 보존됐으며 모든 서로 다른 삼각형 쌍 범위에서 자기 접촉이 검출되지 않았다. 이는 주변 혈관과의 충돌 검사를 포함하지 않는다.

[편집 전후 단면 측정](evidence/access-radius-sections.json)은 같은 중심선의 등간격 33개 위치 중 양 끝을 제외한 31개 평면을 사용한다. 31곳 모두 유일한 중심점 포함 폐곡선을 얻었으며 면적 환산 반경 비율은 1.037732–1.049852였다. 입력 배수와 측정 배수는 구분한다. 이 범위는 표본 단면의 측정값이며 전체 연속 구간의 상하한이나 임상 수용 범위가 아니다.

[주변 관계 비교](evidence/access-radius-context.json)는 동일한 788개 주변 혈관을 대상으로 편집 전후 접촉 삼각형 쌍과 포함 관계를 비교한다. 원본·편집 표면 해시와 context 해시를 고정한다. 검사 진행 중 상태는 RUNNING이며 기존 접촉 또는 미확정 관계가 남으면 전체 PASS로 승격하지 않는다.

## 편집 세션 연결

공통 반경 세션은 전체 접근 모델의 그래프 구간 수와 고유 ID를 확인하고, 변형한 표면에서 모든 중심선 구간을 다시 검사한다. 이전 표면의 면 출처 검증과 주변 검사 결과는 무효화한다. 면 소유권 배열 유지와 변형 좌표의 원본 일치 검증은 구분한다.

앱 적용 및 파일 복원 시 주변 검사 PASS와 전체 중심선 검사 PASS를 모두 요구한다. 반경 저장 파일의 입력 식별에는 전체 접근 그래프와 경로도 포함한다. 그래프가 변경되면 같은 편집 레시피로 간주하지 않는다.

[세션 관련 검사 24개 PASS](evidence/access-radius-session-tests.xml): 전체 중심선 재검사, 원본 검사 결과 무효화, 그래프 누락 거부, 그래프 변경 시 레시피 식별 변경, 주변이 비어 있어도 중심선 이탈 시 적용 차단, 기존 반경 적용·취소·되돌리기·복원 회귀 검사를 포함한다.

데모의 목 메시 개선 후보에 반경 배율·전이 거리·최대 이동 입력과 미리보기 버튼을 연결했다. 동일 원본 case에 연결된 20개 source 경로를 제공한다. FJ1931과 FJ3565는 경로가 여러 개이므로 편집을 비활성화하고 분지 경로 지정이 필요함을 표시한다. 원본 Atlas는 보존한다.

[연결 검사 19개 PASS](evidence/access-radius-ui-prerequisites.xml), [실제 브라우저 검사](evidence/resampled-access-ui.json): FJ2074 선택 시 미리보기 활성화, FJ1931 선택 시 비활성화와 사유 표시, 적용 초기 비활성화, 표면·중심선 전환 및 Atlas 복원을 확인했다. 실제 반경 요청부터 전체 검사 종료·표시·취소까지의 브라우저 왕복은 현재 재검증 중이다. UI 노출을 전체 편집 검증 완료로 해석하지 않는다.

브라우저 왕복 검사는 `scripts/verify_access_radius_roundtrip.cjs`로 시작했다. [실행 기록](evidence/access-radius-roundtrip.json)의 RUNNING은 요청 처리 중이며 완료가 아니다. 고정 조건은 FJ2074, 배율 1.05, 전이 10 mm, 이동 제한 1 mm다. 실제 요청 응답과 65개 중심선·788개 주변 혈관 검사 범위를 확인한 다음, 적용 조건 미충족 시 UI와 서버 양쪽의 거부를 검사하고 미리보기 취소 후 입력 표면 해시 및 Atlas 복원을 확인한다. 계산 중인 서버를 재시작하지 않는다.

반경 처리 진행 상태는 형상 계산/자기 접촉 검사, 중심선 검사, 주변 검사로 나누며 각 단계의 완료 수/전체 수를 전달한다. 이 수치는 검사 통과율이 아니다. 결과 게시 후 complete, 예외 시 failed를 기록한다. [관련 검사 25개 PASS](evidence/access-radius-progress-tests.xml)는 단계 순서·집계와 콜백 데이터 변경이 검사 결과에 영향을 주지 않음을 포함한다. 진행 상태 UI는 라이브 서버에 반영됐고 실제 실행 중인 요청에서 표시를 확인했다. 새 창의 입력값 동기화 수정은 별도 반영 대기 상태다.

## 접촉 변화 위치

[접촉 위치 기록](evidence/access-radius-contact-locations.json)은 검사 기록의 바이트 해시와 입력·출력 표면 해시를 고정하고, 바뀐 접촉 쌍의 전체 모델 면 ID·source 소유권·LPS 경계 상자·최대 정점 변위를 기록한다. 진행 중 기록은 PARTIAL로 표시한다.

현재 확인된 4개 이웃의 추가 접촉 쌍은 모두 FJ2074 소유 면에서 발생했다.

| 이웃 | 종류 | 추가 쌍 | 제거 쌍 |
|---|---|---:|---:|
| FJ2069 · left descending genicular artery | 동맥 | 9 | 10 |
| FJ2099 · left deep femoral vein | 정맥 | 15 | 14 |
| FJ2102 · left femoral vein | 정맥 | 10 | 8 |
| FJ3484 · left external iliac vein | 정맥 | 5 | 3 |

모두 기존에도 SURFACE_CONTACT였으므로 새 이웃 발생과 접촉 위치/범위 변화를 구분한다. 현재 규칙은 추가 접촉 삼각형 쌍을 적용 실패로 판정한다. 동맥 분지 접합의 정상 관계인지 또는 관통인지에 대한 해부학적 분류는 UNKNOWN이다. 표는 완료된 788개 주변 비교에서 접촉 쌍이 추가된 모든 이웃을 포함한다. 이 실패를 숨기기 위해 배율·이동 허용값·검사 대상을 변경하지 않는다.

전체 비교가 880.998초에 완료됐다. 788/788개 검사, 접촉 이웃 80개, 미확정 11개이며 위 4개 이웃에서 접촉 쌍 추가가 확인되어 최종 FAIL이다. 위치 기록도 전체 완료 기록에 연결해 MEASURED로 갱신했다. 반경 편집의 자기 접촉·중심선 PASS와 주변 관계 FAIL을 별도로 유지한다. 현재 조건의 편집은 적용 대상이 아니다. 실제 브라우저 요청은 별도 실행이며 이 오프라인 결과를 브라우저 왕복 PASS로 대체하지 않는다.

첫 브라우저 왕복에서 서버 HTTP 200 이후 Chromium inspector의 응답 본문 캐시가 만료되어 검증 도구가 실패했다. [실패 기록](evidence/access-radius-roundtrip-inspector-cache-failure.json)을 보존했다. 예외 정리에서 미리보기 취소 및 Atlas 복원은 확인했으나 이 결과는 전체 왕복 PASS가 아니다. 장기 요청의 본문 캐시에 의존하지 않고 HTTP 상태와 실제 앱 상태를 검사하도록 도구를 수정했다. 서버 유휴 상태를 확인한 뒤 단계별 진행 상태 구현을 반영했으며, 재실행은 이 상태의 단계 기록을 포함한다.

[실제 진행 표시 관찰](evidence/radius-live-progress-ui.json): 별도 브라우저에서 실제 진행 중인 요청의 주변 검사 0/788과 중복 요청·화면 전환 비활성화를 확인했다. 관찰 전후 generation과 입력 표면 해시가 보존됐다. 이 검사는 전체 왕복 완료를 의미하지 않는다.

이 관찰에서 새 창의 입력값이 실행 중인 요청 값이 아니라 기본값으로 보이는 문제를 발견했다. 요청의 scale·transition_mm·max_displacement_mm를 서버 snapshot에 전달하고 계산·미리보기 중에는 입력을 잠그도록 수정했다. 실제 요청은 보존하므로 해당 수정의 서버 반영 및 새 창 재검증은 아직 NOT RUN이다. JavaScript 구문 검사와 [기존 세션 회귀 11개](evidence/radius-parameter-state-tests.xml)는 PASS이나 새 입력 상태의 브라우저 검증을 대신하지 않는다.

## 요청 내부의 표면 검사 재사용

반경 형상 생성의 자기 접촉 검사와 주변 관계 검사가 동일한 요청 내 content-addressed 검증 캐시를 공유하도록 연결했다. 정점·면 배열의 shape와 float64/int64 내용 해시가 같을 때만 재사용한다. 외부에서 제공한 PASS 판정을 캐시에 주입하지 않으며, 파일 저장이나 요청 사이 재사용은 하지 않는다. 기존 LRU 32개 제한을 유지하고 실패 검사에서는 많은 접촉 쌍을 보관하지 않는다. 반환한 검사 사본을 수정해도 캐시 판정이 바뀌지 않는다.

[관련 검사 28개 PASS](evidence/radius-validation-reuse-tests.xml): 재사용 전후 정점·면·반경 audit와 전체 이웃 판정의 정확한 동등성, 변경 형상의 재검사, 반환 사본 격리 및 기존 포함·접촉·세션 회귀 검사. 라이브 서버 반영과 실제 전체 모델 시간 비교는 현재 실행 중인 요청 이후에 수행하며 NOT RUN이다. 검사 수·허용오차를 줄여 얻은 최적화가 아니다.
