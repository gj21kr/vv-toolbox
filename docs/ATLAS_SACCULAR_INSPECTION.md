# Atlas 파생 경로의 낭상 후보 생성 검사

전체 동맥 snapshot을 context로 유지한 채 좌우 ACA·MCA 네 경로에 고정된 수동 설계를 적용했다. 생성 성공은 **0/4**이며 원본 snapshot은 변경하지 않았다. 이 결과는 해당 위치에서 실제 동맥류가 불가능하다는 판정이 아니라 현재 생성기와 배치 규칙의 적용 실패다.

## 고정 입력

- 각 추출 edge의 호길이 중간 지점. 해부학적 질환 위치나 구간 경계로 해석하지 않는다.
- 좌우 외측 방향을 국소 접선에 수직으로 투영해 목 방향을 정한다.
- 목 2×1 mm, 주머니 4×3×5 mm, 내부 연결 길이 0.5 mm.
- 격자 간격 0.15 mm, 최대 2,000,000개 격자점.
- 주변 edge를 제거하거나 통과 위치를 탐색하지 않았다. 문헌 기반 질환 프리셋이 아닌 공학적 입력이다.

첫 실패에서 중단하므로 각 행은 다른 검사가 통과했다는 의미가 아니다. 임상적 위치·병변 타당성, 실제 원본 표면과의 일치, 기본 앱 적용은 검증하지 않았다.

## 재현

### 우측 MCA 목 평면의 부모·병변 분리 진단

[단면 진단](evidence/mca-saccular-attachment.json)에서 선언된 목 윤곽 64점 중 **37점이 기존 부모 프로파일 내부**에 있었다. 최저 parent field는 −0.406881 mm였다. 같은 평면의 부모·sac 합집합도 하나의 연결 영역이므로 큰 단면을 단순히 다른 독립 contour로 제거할 수 없다. 현재의 합집합 방식은 부모 내부의 점을 외부 목 윤곽으로 보존할 수 없어 부착 방식 개선이 필요하다.

진단 그림 `exports/mca-saccular-attachment/neck-plane.png`를 열람했다. 파랑은 부모, 빨강은 설계 sac, 점선은 합집합, 주황은 부모 내부의 선언된 목 표본이다. ±12 mm 진단 창은 전체 부모 단면을 자르므로 이 창에서 얻은 span을 실제 목 치수로 쓰지 않는다. 원본 OBJ의 내강을 측정한 것이 아니라 파생 반경 프로파일을 검사한 결과다.

생성기 v6는 목 윤곽이 부모 내부에 있는지 격자 할당 전에 검사한다. 1e-6 mm는 수치 부호 판정용이며 기존 치수 허용오차를 바꾸지 않는다. 표본 검사이므로 연속 윤곽 전체의 분리 증명은 아니다. 실제 MCA 입력에서 **37/64 부착 실패를 조기 거부**했고, 기존 표면·마스크·명세 및 새 입력 보존 검사 **47 passed, 7.85초**다. 정상 후보 생성 성공은 여전히 0/4다.

### 우측 MCA 계산 영역 보완 후 재검사

생성기 `saccular-sidewall-5`는 부모 중심선과 반경을 목 좌표계에서 직접 둘러싸도록 계산 영역을 변경했다. world 축 경계상자를 다시 회전시키는 중복 확장을 제거했다. 회전·이동 불변성, 보간된 부모 반경의 영역 포함, 기존 표면/마스크/설계 검사 **46 passed, 7.81초**다.

기존 설계와 0.15 mm 간격에서 필요 격자는 215×90×130 = **2,515,500개**다. [기존 200만 한도 재검사](evidence/mca-saccular-grid-recheck.json)는 여전히 FAIL이다. [300만 한도의 별도 진단](evidence/mca-saccular-grid-recheck-3000000.json)은 자원 한도만 바꾸었으며 품질 허용오차를 바꾸지 않았다. 이 진단에서는 생성 표면의 지정 평면 단면 폭·깊이가 약 **17.977×8.920 mm**로 측정되어 요청한 2×1 mm 및 0.30 mm 오차 조건에 실패했다. 전체 1,081개 context edge와 원본 snapshot을 유지했으며 표면은 게시하지 않았다.

이 값은 지정 평면의 전체 단면 결과로, 병변 목 자체가 그 크기로 생성됐다는 확정 측정은 아니다. 실제 굽은 부모가 같은 평면을 다시 지나는 영향과 국소 부착 형상을 구분하는 검사가 다음 단계다. 예산 문제 해결을 실제 Atlas 후보 성공으로 해석하지 않는다.

Docker에서 `PYTHONPATH=src python scripts/inspect_atlas_saccular_candidates.py`.

[검사 JSON](evidence/atlas-saccular-candidates.json)에 snapshot revision·SHA-256, 전체 context edge 수, 계산 가능한 세 경로의 설계 명세와 실패 사유를 보존했다. 좌 MCA는 방향 계산 단계에서 중단되어 설계 명세를 만들지 못했다. 표면은 하나도 게시하지 않았다.
